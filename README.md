# 카카오톡 RPG 챗봇 (Cloudflare Workers + D1)

공식 카카오 챗봇 관리자센터(오픈빌더) 스킬 API를 사용하는 RPG 게임입니다. 기존 사용자 ID와 캐릭터 데이터는 D1에 저장됩니다.

## 게임 명령어

| 사용자 발화 | 기능 |
| --- | --- |
| 게임시작 | 캐릭터 생성 및 내정보 |
| 사냥 / 탐험 | 1초 간격 공격, 내가 준 피해량·몬스터 HP·레벨 표시 |
| 내정보 | 레벨·스탯·골드·현재/최대 스태미나 |
| 출석 | 7일차 달성 시 최대 스태미나 영구 +10 |
| 출석현황 | 7일 출석 달성 현황과 보상표 |
| 휴식 | 스태미나 잔량과 다음 자동 회복 시각 |
| 사냥터 | 새로운 몬스터 등장·현재 몬스터 레벨·최대/남은 체력 확인 |
| 스탯 | 미사용 스탯 포인트 확인 |
| 힘 올리기 / 방어 올리기 / 민첩 올리기 | 스탯 1포인트 사용 |
| 랭킹 | 상위 10명 표시 |
| 도움말 | 전체 명령어 |

**사냥 결과**는 스태미나 잔량, 내 공격 피해량, 몬스터 레벨·HP를 보여 줍니다. 기본 최대 스태미나는 **100**입니다. 몬스터 HP는 DB에 저장되며, 처치하면 보상과 함께 다음 스테이지 몬스터가 등장합니다.

### 추천 편의 기능

- **스태미나 자연 회복**: 기본 최대 100(7일 출석 달성마다 영구 +10), **10분마다 +1**. 서버는 사용자가 명령어를 보낼 때 경과 시간을 계산하여 실제 잔량에 반영합니다. 별도의 예약 작업이 필요하지 않습니다.
- **출석 보너스**: 스태미나가 부족할 때 출석으로 보충할 수 있고 골드 보상도 함께 지급합니다.
- **휴식 / 출석현황**: 다음 회복 대기시간 및 연속 출석 상황을 채팅창에서 확인합니다.
- **탐험**: 사냥과 같은 전투 명령어 별칭입니다.

### 7일 연속 출석 보상

| 일차 | 골드 | 스태미나 |
| --- | ---: | ---: |
| 1 | 100G | +3 |
| 2 | 200G | +3 |
| 3 | 300G | +4 |
| 4 | 400G | +4 |
| 5 | 500G | +5 |
| 6 | 700G | +5 |
| 7 | 1,200G | +10 |

- 기준 날짜: **한국시간(Asia/Seoul) 자정 00:00**
- 매일 연속 출석 시 다음 일차로 진행합니다. 하루를 놓치면 1일차로 초기화됩니다.
- 7일차 보상을 받고 다음 날 출석하면 다시 1일차부터 시작합니다.
- 동일 날짜 중복 출석은 보상 없이 안내만 표시합니다.
- 7일차 출석을 완료할 때마다 **최대 스태미나가 영구적으로 +10** 증가합니다(100 → 110 → 120 → 130…).
- 출석 스태미나 보상은 증가한 최대치까지만 적용됩니다. 실제 수령량을 메시지에 표시합니다.

## 필수: 기존 D1에 신규 DB 스키마 적용

기존 서비스가 이미 운영 중이라면 **신규 캐릭터 데이터 초기화 없이** 아래 SQL을 한 번만 적용하세요.

1. Cloudflare → Storage & Databases → D1 → **kakao-rpg-db** → Console 열기
2. [migrations/0002_attendance_stamina.sql](migrations/0002_attendance_stamina.sql) 파일 내용 전체를 Console에 붙여넣고 실행
3. 다음 쿼리로 신규 컬럼 4개 확인

```sql
PRAGMA table_info(players);
```

**중요:** 이 ALTER SQL은 같은 데이터베이스에서 **한 번만** 실행해야 합니다. 기존 users / 스태미나 / 경험치 / 골드는 변경하지 않으며, 새 컬럼만 추가합니다. 실행 전 D1 백업도 권장합니다. DB 업데이트가 아직 안 된 경우 기존 사냥은 작동하지만 출석/자동 회복은 준비 중으로 표시됩니다.

### 0003 추가 업데이트: 영구 최대 스태미나와 몬스터

위의 0002 스키마를 이미 적용했다면 **다시 실행하지 말고**, [0003_monsters_stamina_capacity.sql](migrations/0003_monsters_stamina_capacity.sql)만 이어서 **한 번** 실행하세요.

0003은 현재 스태미나를 기본 최대 100으로 한 번 채우고, 영구 최대치, 몬스터 종류·레벨·남은/전체 HP 컬럼을 추가합니다. 캐릭터 레벨·경험치·골드 및 출석 기록은 유지됩니다. 기존 7일 출석 달성에는 영구 보너스를 소급 지급하지 않으며, 업데이트 이후 완료하는 7일차부터 적용됩니다.

신규 블록은 `사냥터` 사용자 발화로 만들고, `RPG_GAME_API` 스킬 / `스킬데이터 사용` 응답에 연결하세요. 기존 `사냥`과 `탐험`도 그대로 작동합니다.

**적용 순서:** 0002가 없다면 먼저 0002 → 0003 → Cloudflare 최신 빌드 Ready 확인 → 카카오 `사냥터` / `사냥` / `출석` 테스트. 각 ALTER SQL은 반복해서 실행하면 안 됩니다.

### 0004: 스탯 실제 전투 적용 / 플레이어 HP (추가 설치)

- 힘 +1 → 기본 공격력 +3
- 방어 +1 → 최대 HP +8, 몬스터 반격 피해 2 감소. 기존 보유 HP도 +8 보충.
- 민첩 +1 → 치명타 확률 +1%p (최대 45%), 반격 회피 확률 +2%p (최대 40%).
- 몬스터가 살아 있으면 55% 확률로 반격할 수 있으며 방어력과 회피율을 적용합니다.
- 플레이어 HP는 D1 DB에 저장되고 5분마다 +10 자연 회복합니다. 체력이 0이면 회복 전까지 사냥 불가.
- 레벨업할 때 스탯 포인트 +1을 주고 `스탯`, `힘 올리기`, `방어 올리기`, `민첩 올리기`에서 분배합니다.

**기존 설치 필수 작업**: Cloudflare D1 → kakao-rpg-db → Console에서 [0004_player_hp.sql](migrations/0004_player_hp.sql) 내용을 한 번만 실행하세요. 먼저 0002/0003을 적용한 상태여야 합니다. 기존 캐릭터의 레벨, 골드, 포인트, 장비, 출석은 보존하고 새 HP만 현재 레벨·방어에 맞춰 최초 최대치로 채웁니다.

**카카오 챗봇 블록 필수**: `힘 올리기`, `방어 올리기`, `민첩 올리기` 세 명령어 각각 사용자 발화를 가진 블록을 생성하고, 스킬 `RPG_GAME_API` / 봇 응답 `스킬데이터 사용`으로 연결해야 버튼이 정상 동작합니다. 사용자 발화가 없다면 폴백 메시지 '무엇을 원하는지 잘 모르겠어요'가 출력됩니다. 기존 `스탯` 블록은 유지하세요.

**테스트**: `스탯` → `힘 올리기` → `스탯`에서 남은 포인트 -1 / 힘+1 / 공격력+3, 다음 `사냥` 결과에서 피해량 확인. 동일한 방식으로 방어/민첩 테스트.

### 0005: 자동 전투 + EXP 퍼센트 + 몬스터 이미지

- 기존 `사냥` 또는 `탐험` 명령 **한 번으로 전투 전체 진행**. 공격과 몬스터 반격을 여러 턴 반복해 몬스터 HP 또는 플레이어 HP가 0이 되면 전투 종료.
- 사냥 1회당 스태미나 1 소모, 최소 사냥 간격 1초는 그대로 유지.
- 전투 요약에 몬스터 레벨, 시작 HP, 총 내가 가한 데미지, 내가 받은 데미지, 라운드 수, 치명타/회피 횟수, 현재 경험치 (`EXP / 목표 EXP (XX.X%)`), 내 HP와 스태미나 표시.
- 몬스터 처치 시 기존과 같은 골드·경험치·레벨업 포인트 지급, 다음 스테이지 몬스터 소환.
- 플레이어가 쓰러지면 보상 없이 플레이어 HP는 0으로 보존하고, 몬스터의 남은 HP는 D1에 그대로 저장합니다. `회복` 또는 시간 경과 자동 회복 후 남은 HP부터 이어서 전투할 수 있습니다.
- 몬스터 종류별로 **6종 자체 제작 픽셀아트 JPEG**를 제공. 카카오톡 기본 카드(`basicCard`)의 썸네일에 이미지 주소 연결. 카드는 전투 결과 및 `사냥터` 조회에서 표시.
- 이미지 엔드포인트: `https://kakao-rpg-bot.bongham.workers.dev/monsters/slime.jpg`, `goblin.jpg`, `wolf.jpg`, `skeleton.jpg`, `golem.jpg`, `knight.jpg` (HTTPS 공개 조회 가능).
- 별도의 D1 마이그레이션은 없음. **이전의 0002, 0003, 0004**를 모두 한 번씩 적용한 상태여야 자동 전투·플레이어 HP 기능이 작동합니다.
- 카카오 관리자센터에서 신규 블록을 만들 필요는 없음. 기존 `사냥`, `사냥터`, `탐험(선택)` 블록에서 `RPG_GAME_API`와 `스킬데이터 사용` 응답을 유지하면 됩니다.
- Cloudflare Workers의 최신 빌드가 `Ready`인지, `/monsters/slime.jpg`를 열었을 때 이미지를 보여주는지, 봇테스트에서 카드와 경험치 퍼센트를 보여주는지 확인하세요.

참고: 자동 전투는 **각 타격마다 카카오 메시지를 연속 발송하는 방식이 아니라** Workers 서버에서 전투를 빠르게 계산한 후 한 번에 결과를 전송하는 구조입니다. 1000턴 이상 장기전일 경우 서버 보호를 위해 탈진 패배로 종료합니다.


### 0006: 회복 명령어 (최대 HP의 45%)

- 신규 발화 `회복`: 누를 때마다 현재 **최대 HP의 45%**를 회복합니다. 소수점이 나오면 올림하며 최대 HP를 넘지 않습니다.
- 예시: 최대 HP 200이면 기준 회복량 +90, 250이면 +113. 현재 HP가 240/250이면 실제 회복량은 +10으로 제한합니다.
- HP가 0이어도 회복할 수 있고, 회복 성공 메시지에 기준 회복량·실제 회복량·현재 HP를 표시합니다.
- HP가 가득 찼다면 DB 변경 없이 만피 안내만 합니다. 기존 레벨·스탯·경험치·출석·몬스터 진행 상태는 유지합니다.
- 전투 결과, 휴식 화면 등에 `회복` 바로가기 버튼을 추가했습니다.
- **추가 DB 마이그레이션 없음**: 기존 0004_player_hp.sql 적용 상태면 됩니다.
- 카카오 관리자센터에서 기존 `휴식` 블록의 사용자 발화에 **`회복`**을 추가한 뒤 저장하세요. (또는 `회복` 블록을 별도로 만들어 같은 `RPG_GAME_API` 스킬/`스킬데이터 사용`으로 등록)
- 테스트는 `내정보` → `회복` → `내정보` 순서로 하고, 체력 수치가 45% 기준으로 늘어났는지 확인합니다.
- 현재 회복 기능은 별도 골드·스태미나 소비나 재사용 대기시간이 없습니다. 추후 밸런스 조정을 권장합니다.


### 0007: 전투 결과 가독성 개선 및 패배 시 몬스터 잔여 HP

- 전투 응답을 `몬스터 이름·레벨·시작 HP → 전투 기록 → 전투 결과 → 누적 피해·회피 → 경험치 퍼센트 → 내 HP → 스태미나` 순서로 정리합니다.
- 승리 문구는 한 번만 출력하고, 전투는 1~3턴 + 마지막 결정타/전투 불능 턴을 보여줍니다. 5턴 이상인 경우 중간에 생략된 턴 수를 표시합니다.
- **승리**: 처치한 몬스터, 골드, 경험치, 다음 등장 몬스터를 표시합니다.
- **패배**: 마지막 공격 직후의 `몬스터 남은 HP A/B`를 표시하고 DB에도 A/B를 저장합니다. 회복 후 다시 `탐험`하면 몬스터 남은 HP부터 이어서 전투합니다.
- 기존 최대 HP의 45% 회복, 스태미나, 전투 보상, 출석 시스템, 몬스터 이미지 카드의 동작은 바뀌지 않습니다.
- DB 변경과 카카오 블록 추가가 필요하지 않습니다. Cloudflare 최신 배포 Ready 후 `사냥`을 테스트하세요.


### 0008: 몬스터 이미지 카드 + 카카오톡 버튼 메뉴

- `사냥터` 명령과 `사냥`/`탐험` 자동전투 결과를 **전투 요약 텍스트 → 몬스터 이미지 기본 카드** 순서로 표시합니다.
- 기본 카드에는 몬스터 이름, Lv, 스테이지, 현재/최대 HP, 짧은 설명, 해당 몬스터의 이미지가 노출됩니다.
- 카드 아래 가로 버튼 2개: **휴식** / **탐험**. 휴식은 기존 `휴식` 발화를 보내고, 탐험 버튼의 표시명은 `탐험`이지만 실제 발화는 `사냥`으로 보내 기존 사냥 블록을 그대로 재사용합니다.
- **전투 결과 카드는 방금 싸운 몬스터를 기준으로 표시**합니다. 승리 시 몬스터 이미지는 그대로 유지하며 카드의 HP 대신 `✅ 몬스터 퇴치 완료`를 표시합니다. 패배 시에는 전투가 끝난 순간의 몬스터 남은 HP를 표시하고, 다음 재도전에서도 그 남은 HP가 유지됩니다.
- 몬스터 JPEG 6종 및 공개 URL은 기존 리소스 `/monsters/<slug>.jpg`를 그대로 사용합니다. `basicCard.thumbnail`은 1:1 비율을 사용합니다.
- 스킬 템플릿 `outputs`는 `simpleText` 1개 + `basicCard` 1개입니다. 카카오 기본 카드의 `buttons`는 `action: message`를 사용합니다.
- **DB 마이그레이션 필요 없음.** 카카오 관리자센터에서 이미 `휴식`과 `사냥` 블록이 등록됐다면 추가 블록 등록도 필요하지 않습니다.
- Cloudflare Workers 최신 배포 확인 후 카카오 봇테스트에서 `사냥터`, `사냥`, 카드 버튼 `휴식`/`탐험`을 순서대로 실행하세요.

### 0009: 플레이어 전투불능 이후 몬스터 체력 유지

- `사냥` 전투에서 플레이어가 패배하면 해당 전투의 `fight.remainingMonsterHp`를 `players.monster_hp`에 영구 저장합니다.
- `회복` 기능은 플레이어 HP만 복원하고 몬스터 HP는 바꾸지 않습니다. 이후 `탐험` / `사냥`에서 같은 몬스터의 저장된 HP를 읽어 전투합니다.
- `사냥터`를 조회해도 HP가 남아 있는 몬스터는 재생성하지 않습니다. 같은 몬스터를 최종 처치하면 다음 스테이지 몬스터가 등장합니다.
- 패배 결과 메시지 및 이미지 카드에 같은 몬스터의 남은 HP가 표시됩니다.
- 기존 D1 컬럼과 카카오 블록을 그대로 사용하므로 별도 마이그레이션은 없습니다. 과거 배포에서 이미 HP가 초기화된 전투는 소급 복구되지 않습니다.

### 0010: 회복 결과 카드 및 바로가기 버튼

- `회복` 명령의 성공 결과를 기존 일반 텍스트 말풍선 대신 카카오 `textCard`로 보여줍니다.
- 카드에는 회복 성공 여부, 기준 회복량(최대 HP 45%), 실제 회복량, 현재 HP를 표시합니다.
- 카드 하단에 가로 버튼 `회복`, `사냥`을 배치하고 각각 기존 명령어 발화를 전송합니다.
- HP가 가득 찬 상태 및 동시 요청으로 인한 재시도 안내도 동일한 카드 메뉴를 사용합니다.
- 이미지가 없는 카드이므로 썸네일을 요구하는 `basicCard`가 아닌 `textCard`를 사용합니다.
- DB 스키마, 기존 캐릭터 HP와 전투 시스템은 변경하지 않습니다. 카카오 관리자센터에 `회복`, `사냥` 발화가 등록되어 있어야 버튼이 동작합니다.


### 0011: 세 직업 / 3단계 전직 / 스탯 초기화

| 단계 | 레벨 | 전사 | 도적 | 마법사 |
|---|---:|---|---|---|
| 1차 | 20 | 전사 | 도적 | 마법사 |
| 2차 | 100 | 수호기사 | 암살자 | 원소술사 |
| 3차 | 500 | 전쟁군주 | 그림자 군주 | 아크메이지 |

Lv.20에 계열을 선택하고 이후 Lv.100/500에는 동일 계열로 승급합니다. 이미 고레벨인 기존 유저도 1차부터 순서대로 승급합니다.

**전직 확인 화면**에서 새 직업과 자동 스킬, 스탯 초기화 경고, 돌려받을 포인트를 보여 줍니다. 전직 확정 전에는 능력치가 변경되지 않으며 취소도 가능합니다.

**전직 확정** 시 힘/방어/민첩/지능은 각각 5로 초기화하고, 이미 투자한 포인트를 전액 미사용 포인트로 돌려줍니다. HP를 리셋된 최대치까지 채웁니다. 레벨/EXP/골드/스태미나/출석/몬스터 HP는 유지합니다. 낙관적 잠금으로 중복 전직과 포인트 중복 지급을 방지합니다.

**자동 스킬**: 전사(피해 감소 → 반사 → 전투당 1회 생존), 도적(추가 공격 → 치명타 피해 2배 → 첫 3턴 분신), 마법사(파이어볼 → 원소 폭발 → 메테오). 마법은 지능 1 증가 시 추가 주문 공격력 +4를 적용합니다.

**D1 필수 업데이트**: 0004까지 적용된 기존 운영 DB에 [0005_job_advancement.sql](migrations/0005_job_advancement.sql)을 한번만 실행합니다. 추가되는 필드는 job_class / job_tier / intelligence 세 개이며 기존 데이터는 그대로 보존합니다. 적용 전에 D1 백업을 권장합니다.

**카카오 챗봇 오픈빌더 설정**: 시나리오에서 하나의 '전직' 블록에 사용자 발화 9개를 추가하세요.

전직 / 전사 선택 / 도적 선택 / 마법사 선택 / 전사 전직 확정 / 도적 전직 확정 / 마법사 전직 확정 / 전직 확정 / 전직 취소

전직 블록은 RPG_GAME_API 스킬 + 스킬데이터 사용으로 설정합니다. 기존 '스탯' 블록에는 '지능 올리기' 발화를 추가합니다.

**테스트**: Lv.20+ 캐릭터로 전직 → 도적 선택 → 스탯 초기화 안내 확인 → 전직 확정 → 스탯 → 민첩 올리기 → 사냥을 실행해 봅니다.


### 0012: 스탯 포인트 일괄 투자

- 기본 `힘 올리기`, `방어 올리기`, `민첩 올리기`, `지능 올리기`는 기존처럼 1포인트씩 사용합니다.
- `힘 올리기 24`, `방어 올리기 10`, `민첩 올리기 5`, `지능 올리기 3`처럼 명령 뒤에 양의 정수를 붙이면 그 수만큼 한 번에 분배합니다.
- 현재 미사용 스탯 포인트보다 많이 요청하면 일부만 사용하는 대신 전체 요청을 거절합니다. 0, 음수, 소수, 숫자가 아닌 입력도 거절합니다.
- DB의 능력치 증가와 포인트 차감을 단일 조건부 UPDATE로 처리하고, version을 확인해 중복 사용을 방지합니다. 방어 N포인트 투자 시 현재 HP가 함께 8×N 증가합니다.
- DB 스키마 변경은 없습니다. 기존 캐릭터/전직 포인트도 동일하게 사용할 수 있습니다.
- **중요:** 카카오 오픈빌더가 `힘 올리기 24`처럼 숫자가 붙은 발화를 RPG_GAME_API 스킬로 전달하도록 블록 패턴 또는 폴백 발화를 설정해야 합니다. 숫자가 붙은 문장을 봇이 인식하지 못하면 Worker까지 요청이 도착하지 않으므로 단순 Worker 수정만으로는 처리되지 않습니다.

### 0013: 단일 슬롯 등급 장비 / 인벤토리 / +20 강화

**장비는 종류가 없습니다.** 무기·갑옷·반지 슬롯을 구분하지 않고, 캐릭터당 딱 **1개의 장비 슬롯**에 착용합니다. 모든 아이템 이름은 `장비`이며 **등급과 강화 수치**만 다릅니다.

| 등급 | 사냥 드롭 시 등급 비중 | 기본 공격력 |
|---|---:|---:|
| ⚪ 일반 | 60% | +5 |
| 🔵 희귀 | 25% | +12 |
| 🟣 영웅 | 10% | +24 |
| 🟠 전설 | 4% | +42 |
| 🔴 신화 | 1% | +70 |

- **드롭**: 몬스터 최종 처치(사냥 승리)마다 18% 확률로 장비를 1개 획득합니다. 표의 등급 비중은 **드롭에 성공했을 때**의 비중입니다.
- **첫 장비**: 착용 장비가 전혀 없는 상태에서 드롭되면 자동 착용됩니다. 이미 착용 중이라면 새 장비의 **등급이 다르더라도 기존 착용 장비는 유지**하고 새 장비는 인벤토리에 저장됩니다. 같은 등급의 중복 장비도 별도 인벤토리에 보관합니다.
- **전투**: 착용 장비의 공격력 보너스가 전사/도적/마법사 일반 타격 및 마법 피해에 적용됩니다. 장비를 교체하면 그 다음 전투부터 적용됩니다.
- **메뉴**: `장비`에서 현재 착용 장비·강화확률·비용 조회, `인벤토리`에서 장비 전체 목록과 번호 확인, `최고 장비 장착` 버튼으로 공격력이 가장 높은 장비를 자동 착용합니다. `장착 12`로 #12 장비 직접 착용, `판매 12`로 미착용 #12 장비 판매, `인벤토리 2`로 2페이지 조회, `강화` → `강화 실행`으로 확률 확인 후 강화합니다.
- **강화**: 착용 장비만 강화 가능, 최대 +20. 등급은 변하지 않으며 강화 성공은 +1, 유지 0, 하락 -1(최저 +0), 파괴는 현재 착용 장비 삭제입니다. 파괴 시 다른 보유 장비는 그대로 남습니다. 결과와 관계없이 골드가 소모됩니다.

| 현재 강화 | 성공(+1) | 유지 | 하락(-1) | 파괴 |
|---|---:|---:|---:|---:|
| +0~+4 | 85% | 15% | 0% | 0% |
| +5~+9 | 65% | 30% | 5% | 0% |
| +10~+14 | 35% | 35% | 25% | 5% |
| +15~+17 | 25% | 30% | 35% | 10% |
| +18~+19 | 15% | 30% | 35% | 20% |

- **강화 골드**: 현재 강화가 n일 때 기본 가격 `80 + 35 × (n+1)^2`에 등급 배수(일반 1.0 / 희귀 1.35 / 영웅 1.8 / 전설 2.4 / 신화 3.2)를 곱하고 반올림합니다. 스테이지에는 영향받지 않습니다.
- **공격 보너스**: 등급 기본 공격력 × `(1 + 0.17×강화수치 + 0.022×강화수치²)`를 반올림합니다. 강화를 내리면 공격 보너스도 내려갑니다.
- **안전성**: 플레이어 행 버전 검증 + D1 배치 트랜잭션으로 드롭/골드 차감/장비 강화/장착을 한 번에 처리합니다. 파괴되어도 레벨과 전직 기록은 손대지 않습니다.

**D1 작업 필수:** 기존 `0001_initial.sql`에 이미 있는 `equipment` 테이블을 재사용하므로 새 테이블은 필요하지 않습니다. 운영 D1에서 [0006_equipment_slot.sql](migrations/0006_equipment_slot.sql)을 **한 번** 실행해 캐릭터당 착용 슬롯 1개를 보장하는 인덱스를 만드세요. 전직 마이그레이션이 미적용 상태라면 `0005`를 먼저 적용합니다. D1 백업 권장.

**카카오 오픈빌더:** `장비`, `인벤토리`, `최고 장비 장착`, `강화`, `강화 실행`을 한 블록 또는 각각 등록하고 `RPG_GAME_API` 스킬 + 스킬데이터 사용으로 연결합니다. 숫자가 붙는 `장착 12`, `판매 12`, `인벤토리 2` 등의 명령은 **숫자 자리를 받는 발화 패턴 또는 폴백 스킬 라우팅**을 설정해야 합니다. 일반 고정 발화만 있으면 숫자 명령은 카카오 오픈빌더에서 매칭되지 않을 수 있습니다.

**테스트:** `사냥`으로 드롭 → `장비` 확인 → `인벤토리` 확인 → `강화`에서 단계별 확률 확인 → `강화 실행` → `장착 <번호>`로 다른 등급 교체. 강화 결과에 따라 보유 골드·보너스·장비 상태가 갱신되는지 확인하세요.


### 0014: 5종 장비 이름 / 무기·갑옷·반지 3슬롯

> 이 절이 0013의 '장비 종류 없음/1슬롯' 규칙을 대체합니다. 기존 캐릭터/강화 데이터를 삭제하지 않고 확장합니다.

| 등급 | 검 | 단검 | 지팡이 |
|---|---|---|---|
| ⚪ 일반 | 낡은 철검 | 무딘 단검 | 견습 마법사의 지팡이 |
| 🔵 희귀 | 청명의 강철검 | 달빛 은단검 | 푸른 룬의 지팡이 |
| 🟣 영웅 | 흑염의 마검 | 그림자 송곳니 | 별빛 현자의 지팡이 |
| 🟠 전설 | 뇌신의 심판검 | 망령군주의 암살도 | 심연의 성좌 마도봉 |
| 🔴 신화 | 태초를 가르는 천상검 | 영겁을 찢는 그림자 칼날 | 창세의 아스트랄 홀 |

| 등급 | 갑옷 | 반지 |
|---|---|---|
| ⚪ 일반 | 낡은 가죽갑옷 | 빛바랜 은반지 |
| 🔵 희귀 | 강철 수호갑옷 | 푸른 달의 계약반지 |
| 🟣 영웅 | 용비늘 전투갑옷 | 비전의 마력반지 |
| 🟠 전설 | 불멸왕의 수호갑주 | 운명을 지배하는 왕의 반지 |
| 🔴 신화 | 천상의 창세갑주 | 무한의 창세 반지 |

- 장착 슬롯은 **무기 1개(검·단검·지팡이 중 1개) + 갑옷 1개 + 반지 1개**입니다. 같은 슬롯에서 새로운 장비를 장착하면 이전 장비는 인벤토리에 남습니다.
- 모든 장비는 이름·등급·강화 단계가 저장됩니다. 장비 타입에 따라 전투 효과가 다릅니다: 검은 **기본 공격력**, 단검은 **공격력+치명타 4%p**, 지팡이는 **공격력+마법 스킬 추가 피해(장비 공격 수치의 1/3 올림)**, 갑옷은 **받는 피해 감소**, 반지는 **공격력과 치명타 확률**을 제공합니다. 효과는 착용 시에만 전투에 반영됩니다.
- 사냥 승리 시 장비 드롭 **18%**는 유지합니다. 드롭된 장비의 종류 비중은 검 22%, 단검 18%, 지팡이 20%, 갑옷 24%, 반지 16%이며 등급 비중(일반 60%, 희귀 25%, 영웅 10%, 전설 4%, 신화 1%)은 기존과 같습니다.
- 새로 얻은 장비는 **해당 슬롯이 비어 있을 때만 자동 장착**하며, 해당 슬롯에 이미 장착 중인 장비가 있다면 인벤토리에 보관합니다. 다른 종류·등급의 장비를 얻더라도 기존 착용 장비를 자동 덮어쓰지 않습니다.
- **강화는 각 슬롯별로 따로 수행**합니다. `강화` 버튼을 누르면 `무기 강화`, `갑옷 강화`, `반지 강화`를 고를 수 있고 해당 슬롯의 확률·비용·파괴 위험을 확인한 뒤 `무기 강화 실행` 등으로 수행합니다. +20 제한과 +10~14 파괴 5% 등 강화 확률 및 가격 공식은 기존과 동일합니다.
- `장비` 명령으로 3슬롯 착용 현황을 보며, `인벤토리`와 `장착 {번호}` / `판매 {번호}`는 이전과 동일합니다. `최고 장비 장착`은 기존보다 수치가 높은 미착용 아이템을 하나씩 자동 장착하며, 여러 슬롯을 교체할 때는 반복해서 사용할 수 있습니다.
- 이전 0013 단계의 일반 장비(`item_code='single'`)는 DB SQL 적용 시 **검**으로 전환되며 **등급·강화수치·공격력·장착여부가 유지**됩니다.
